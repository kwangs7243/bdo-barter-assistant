- 파일: `reference/original/물물교환 지능형 스케쥴러_배포용 v14.1_by 송도조씨.html`
- 크기: 508,642 bytes
- SHA-256: `155EE19C515A72627EFFB4884F540BBD7FCEA487967C47FE6CCB3A608BCEAE9F`
- 조사일: 2026-09-22

파일명은 v14.1이지만 HTML `<title>`과 화면 제목은 `V14.0`으로 표시된다. 이 문서는 파일명을 기준으로 v14.1 reference라고 부르되, 내부 버전 표기 불일치를 사실로 남긴다.

이 파일은 단일 HTML에 UI, 로컬 저장, Gemini 이미지 분석, 품목/좌표 데이터, 스케줄 엔진, 지도·진단 기능이 함께 들어 있는 참고 구현이다. 새 앱에서는 책임을 분리한다.

## 2. `masterData`

`masterData`는 단계 번호를 키로 하고 `{name, stock}` 배열을 값으로 가진다.

| 단계 | 품목 수 |
|---:|---:|
| 1 | 14 |
| 2 | 14 |
| 3 | 14 |
| 4 | 14 |
| 5 | 14 |
| 6 | 24 |
| 7 | 24 |
| 합계 | 118 |

확인된 역할:

- 품목 단계 판별 (`getItemTier`)
- UI datalist 후보
- OCR 결과의 알려진 품목 후보
- 초기 재고 구조 생성

이식 방침:

- 품목명과 단계는 파생 reference data로 이식한다.
- 원본에 들어 있는 `stock`은 사용자별 시점 값이므로 새 앱의 기본 재고로 이식하지 않는다.
- 새 재고는 미확인 상태로 시작하며 사용자가 확인한 값만 저장한다.

## 3. `rawData` / `islandCoordinates`

원본은 `rawData`에 좌표 객체를 정의한 뒤 깊은 복사로 `islandCoordinates`를 만든다.

- 좌표 키: 100개
- 일부 키는 같은 위치를 가리키는 별칭이다. 예: `해모 섬`/`해모`, `깊은 밤의 항구`/`깊은 밤`.
- 일부 대양 지점은 `isOcean: true`를 가진다.
- `일리야`는 `(0, 0)` 기준점이다.
- 좌표를 못 찾으면 `getIslandCoords`가 `{-150, 0, false}`를 반환한다. 이는 호환 구현 시 명시적으로 테스트해야 할 fallback이다.

이식 방침:

- canonical 섬/지점과 aliases를 분리한다.
- 좌표와 `is_ocean`은 reference data로 이식한다.
- 알 수 없는 섬에 조용히 임의 좌표를 부여할지는 동등 재현 테스트에서 분리해 기록한다.

## 4. `defaultRouteCalibrations`

원본에는 방향성 있는 항로 키 14개의 기본 multiplier가 있다.

```text
route key: "출발지_도착지"
value: { multiplier: number }
```

확인된 동작:

- `window.routeCalibrations`는 기본값 위에 사용자 `localStorage` 값을 덮어쓴다.
- `applyOceanCurrent(nameA, nameB, dist)`가 정확히 일치하는 방향 키의 multiplier를 적용한다.
- A→B와 B→A를 같은 키로 정렬하지 않으므로 방향별 보정이 가능하다.
- 그란디하/깊은 밤과 본토 사이 거리는 `legDistance`에서 시오닐 섬을 경유한 두 구간으로 계산하는 특례가 있다.

이식 방침:

- 기본 14개 보정값과 방향성을 보존한다.
- 사용자 보정은 기본 reference와 별도 로컬 설정으로 저장한다.
- 좌표·보정값의 편집 UI는 M5 동등 재현에 필요하지 않으면 후순위다.

## 7. 스케줄 엔진 호출 구조

```text
runAlgorithmAllModes
  ├─ 활성 교환 필터링
  ├─ 품목명 정리, 단계/배율/무게 매핑
  ├─ 상위 단계부터 하위 단계로 동적 수요 전파
  ├─ 결핍·단계·보존·특수·까주 점수 계산
  ├─ 교역 모드에 따른 대양/7단 필터
  ├─ 일반 모드
  │    ├─ buildSorties(..., "speed")
  │    └─ buildSorties(..., "balance")
  └─ 7단 모드
       ├─ buildTier7Sorties(..., "speed")
       └─ buildTier7Sorties(..., "balance")
```

### 7.1 전처리와 동적 수요

- `scannedTrades`에서 삭제, 비활성, 0회, 필수 필드 누락을 제외한다.
- 품목명에서 단계 표기와 `xN` 표기를 제거하고 `masterData`로 단계를 찾는다.
- 기본 교환 배율과 품목 무게를 적용한다.
- 4→5단은 잔여가 5회 이상이면 5회, 1~4회면 제외하는 규칙이 있다.
- 까마귀 주화는 섬 분류에 따라 1회 또는 4회로 실행 횟수를 조정한다.
- 7, 6, coin, mat, 5, 4, 3, 2, 1 순으로 상위 교환의 소모 수요를 하위 품목 목표에 전파한다.

### 7.2 점수

확인된 주요 입력:

- 현재 재고와 목표 재고의 결핍
- 단계별 기본 가점
- 보존/긴급 가점
- 특수 재료와 까마귀 주화 우선도
- 연쇄 가점
- 거리 감점
- 길목 반경과 가점
- 권역 이탈 감점
- 소량 교환 감점
- 과적 시간 가중

점수는 후보 우선순위를 정하지만 이후 교섭력, 재고, 무게, 권역, 연쇄 가능성 gate에서 다시 제한된다.

### 7.3 일반 `buildSorties`

- 남은 교환에서 출항별 seed와 허용 권역을 정한다.
- 교섭력 예산에서 VIP 성격의 5단, 특수 재료, 까마귀 주화를 보호한다.
- 내해/대양 까마귀 주화 버스와 일반 재료 출항을 구분한다.
- JIT 공급, 연쇄 가능성, 창고 보존량, 권역, 길목, 거리, 무게, 교섭력을 평가해 다음 교환을 고른다.
- 대양 고정 순서와 TSP형 근접 정렬을 함께 사용한다.
- `speed`는 100% 무게와 귀환 과적을 엄격히 제한한다.
- `balance`는 최대 무게 한도까지 허용하되 별도 과적 시간 비용을 계산한다.
- 생성 후 무게 위반을 줄이고, 작은 조각 출항 병합을 시도한 뒤 다시 무게와 연쇄를 검증한다.

### 7.4 경로 최적화와 시간

- 교환이 7개 이하면 `getOptimalRoute`가 모든 순열을 검사한다.
- 연쇄 선행 재료가 없는 순열은 제외한다.
- 후보별 `simulateWeightsTemp` 총시간이 가장 짧은 순서를 선택한다.
- 7개를 넘으면 `optimizeRouteTSP`의 최근접 휴리스틱을 사용한다.
- 시간 시뮬레이션은 시작/구간/귀환 무게, 과적 여부, 선박 배속, 항로 multiplier를 반영한다.

### 7.5 7단 `buildTier7Sorties`

지역 조합:

- `t7_3region`: 동부 + 서부 + 남부
- `t7_2region`: 동부 + 서부
- `t7_2region_south`: 동부 + 남부
- `t7_2region_arehazaX`: 서부 + 남부

확인된 흐름:

1. 지역별 6단 교환과 필요한 5단 재료를 계산한다.
2. 지정된 5단 공급 섬에서 재고와 교섭력이 허용하는 묶음을 만든다.
3. 6단 결과를 가상 화물로 쌓고 연결 가능한 7단 교환을 붙인다.
4. 일반 1회 까마귀 주화 노드를 지역별 고정 노선에 포함할 수 있다.
5. 6/7단 본대는 쾌속/균형 표시와 관계없이 100% 무게를 넘지 않게 보호한다.
6. 귀환 길목의 결핍 1~4단을 제한적으로 추가하는 vacuum return을 수행한다.
7. 남은 1~5단/coin/mat은 잔여 교섭력과 가상 재고를 적용해 일반 `buildSorties`로 넘긴다.

## 8. 가져올 것과 버릴 것

### 가져올 것

- `masterData`의 품목명과 단계
- `rawData`/`islandCoordinates`의 좌표, 별칭, 대양 표시
- `defaultRouteCalibrations`와 방향성
- `APP_CONFIG`의 계산 관련 기본값
- 교환 배율과 무게 규칙
- 동적 수요, 점수, 권역, 연쇄, 무게, 교섭력 계산
- 쾌속/균형 결과와 7단 지역 조합
- 시간 시뮬레이션과 항로 특례

### 새 앱에 가져오지 않을 것

- Gemini API 호출
- API 키와 AI 모델 선택 UI
- 브라우저 화면 공유/캡처 구현 자체
- Tailwind CDN 의존 UI
- 원본 로컬스토리지 키 구조를 그대로인 저장 계약으로 사용
- 제작자용 튜닝 지도, 진단 복사, 자유 항로 타이머 등의 부가 UI
- 원본 재고 숫자와 개인 설정값

부가 기능이 나중에 필요하면 제품 요구사항으로 다시 승인받아 별도 마일스톤에 추가한다.

## 9. 동등 재현 시 주의점

- 파일명과 내부 버전 표기가 다르다.
- 원본은 UI DOM 값, `APP_CONFIG`, localStorage가 함께 계산 입력이 된다.
- 같은 설정의 fallback 값이 함수마다 다를 수 있다.
- 좌표 별칭과 알 수 없는 좌표 fallback이 결과에 영향을 줄 수 있다.
- 원본은 계획 계산 중 가상 재고를 임시 변경한 뒤 복원하는 구간이 있다.
- 표시 직전 병합과 순서 후보정이 엔진 결과를 바꿀 수 있다.
- 함수 주석의 버전명보다 실제 코드를 기준으로 fixture를 만든다.
- 동등성은 단순 최종 섬 순서뿐 아니라 실행 횟수, 시작/최고 무게, 귀환 과적, 교섭력, 요구 재료를 비교해야 한다.
